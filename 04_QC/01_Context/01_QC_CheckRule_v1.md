# QC 검증 규칙 정의서 v1.0

> **문서 목적**: P19 QC 검증 페이지에서 동적으로 로드하여 사용하는 검증 규칙 정의
> **마지막 수정**: 2026-01-17

---

## 검증 카테고리

### 1. 데이터 추출 검증 (data)

| ID       | 항목명           | 방법  | 설명 |
|----------|------------------|-------|------|
| data-1   | CS 데이터 완전성 | LLM   | Draft 보고서의 CS(Context-Specific) 데이터가 추출된 데이터와 일치하는지 확인. 날짜, 숫자, 성분명 등의 정확성 검증. |
| data-2   | PH 데이터 완전성 | LLM   | Draft 보고서의 PH(Paragraph/Phrase) 서술문 데이터가 추출된 데이터와 일치하는지 확인. |
| data-3   | 표 데이터 완전성 | LLM   | Draft 보고서의 표(Table) 데이터가 추출된 데이터와 일치하는지 확인. |
| data-4   | 소스 문서 대조   | LLM   | Draft 보고서의 내용이 원본 소스 문서(RAW 파일)와 일치하는지 확인. 임의 추가/변형 여부 검증. |

---

### 2. 데이터 충돌 검증 (conflict)

| ID         | 항목명              | 방법  | 설명 |
|------------|---------------------|-------|------|
| conflict-1 | 섹션 간 데이터 일치성 | LLM   | 서로 다른 섹션에 동일 데이터가 있을 때 값이 일치하는지 확인. (예: Section 03과 Section 12의 판매량) |
| conflict-2 | 날짜 정보 일관성     | LLM   | 보고서 전체에서 사용된 날짜 정보가 논리적으로 일관성 있는지 확인. |
| conflict-3 | 수치 데이터 일치성   | LLM   | 동일 수치가 여러 위치에 등장할 때 값이 일치하는지 확인. |

---

### 3. 구조 검증 (structure)

| ID          | 항목명           | 방법   | 설명 |
|-------------|------------------|--------|------|
| structure-1 | 표 번호 순서     | REGEX  | 표 번호가 순차적(표1, 표2, 표3...)으로 사용되었는지 확인. 중복/누락 검출. |
| structure-2 | 섹션 번호 순서   | REGEX  | 섹션 번호가 순차적으로 구성되었는지 확인. |
| structure-3 | 참조 문헌 일치성 | LLM    | 본문에서 인용된 참조 문헌이 실제로 참고문헌 목록에 존재하는지 확인. |

---

### 4. 내용 검증 (content)

| ID        | 항목명             | 방법  | 설명 |
|-----------|--------------------|-------|------|
| content-1 | 서술문 소스 대조   | LLM   | PH 서술문의 내용이 해당 RAW 소스 문서의 사실과 부합하는지 확인. 과장/왜곡 검출. |
| content-2 | 템플릿 구조 준수   | REGEX | 보고서가 정해진 템플릿 구조(필수 섹션, 헤딩 형식)를 준수하는지 확인. |
| content-3 | 리뷰 변경사항 반영 | LLM   | Stage 7(리뷰)에서 수정된 내용이 최종 Draft에 반영되었는지 확인. |

---

### 5. 규제 준수 검증 (regulatory)

| ID           | 항목명                | 방법  | 설명 |
|--------------|-----------------------|-------|------|
| regulatory-1 | MFDS 가이드라인 준수  | LLM   | 식약처(MFDS) KSUR 가이드라인 요구사항 준수 여부 확인. |
| regulatory-2 | 필수 항목 포함 여부   | REGEX | 규제에서 요구하는 필수 섹션/항목이 모두 포함되어 있는지 확인. |
| regulatory-3 | 용어 정확성           | LLM   | 의약품 안전 관련 용어가 표준 용어(MedDRA 등)와 일치하는지 확인. |

## 검증 방법 정의

### LLM (Large Language Model)
- **설명**: Gemini API를 사용하여 AI가 내용을 분석하고 검증
- **프롬프트 특성**: "Think step by step", "Take your time" 주의 깊은 검증 요청
- **출력 형식**: JSON 형태로 이슈 목록 반환

### REGEX (Regular Expression)
- **설명**: 정규표현식을 사용한 패턴 매칭 검증
- **장점**: 빠른 처리 속도, 일관된 결과
- **적용 예**: 표 번호 순서, 필수 섹션 존재 여부

## 심각도 수준

| 수준     | 코드     | 설명 |
|----------|----------|------|
| 중대     | critical | 보고서 제출 전 반드시 해결 필요. QC 통과 불가. |
| 경고     | warning  | 권장 수정 사항. 해결 없이 진행 가능하나 검토 권장. |
| 정보     | info     | 참고 정보. 수정 선택적. |

## 필수 섹션 목록

```
1. 서론
2. 전세계 판매 승인 현황
3. 시판 후 사용 현황
4. 안전성 정보의 변경
5. 약물이상반응 정보 현황
```
