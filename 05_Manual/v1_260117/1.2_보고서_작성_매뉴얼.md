## 1. 개요

### 1.1 PSUR이란?
**PSUR (Periodic Safety Update Report)** - 정기안전성업데이트보고서
- 의약품 시판 후 일정 기간 동안 수집된 안전성 정보를 종합 분석
- 식품의약품안전처(MFDS)에 정기적으로 제출하는 규제 문서

### 1.2 KPSUR AGENT 역할
- 소스 문서에서 데이터를 자동 추출
- LLM 기반으로 15개 PSUR 섹션 자동 생성
- QC 검증을 통한 품질 확보
- Word 문서 형태로 최종 출력

### 1.3 보고서 작성 권한
- **Author** 역할 이상 필요
- Viewer는 조회만 가능
- Reviewer는 QC 승인 가능

## 2. 워크플로우 전체 흐름

```
┌─────────────────────────────────────────────────────────────────────┐
│                    KPSUR AGENT 5단계 워크플로우                       │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  Stage 1         Stage 2         Stage 3        Stage 4    Stage 5 │
│  ┌─────┐        ┌─────────┐     ┌─────────┐    ┌─────┐    ┌─────┐  │
│  │새보고서│  →   │Raw Data │  →  │섹션 편집 │ →  │ QC  │ →  │출력 │  │
│  │ 생성  │       │  처리   │     │         │    │검증 │    │    │  │
│  └─────┘        └─────────┘     └─────────┘    └─────┘    └─────┘  │
│                                                                      │
│  P13_NewReport  P14_Unified     P15_Section    P19_QC   P20_Output  │
│                 Processing       Editor                             │
│                                                                      │
│  - 기본정보입력   - 파일업로드     - 15개섹션      - 자동검증  - Word생성  │
│  - CS변수입력    - MD변환         - AI편집지원    - 오류확인  - 다운로드  │

```

### 각 단계 소요 시간 (예상)
| 단계 | 예상 소요 시간 | 비고 |
|------|---------------|------|
| Stage 1 | 5~10분 | 수동 입력 |
| Stage 2 | 15~30분 | LLM 자동 처리 |
| Stage 3 | 30~60분 | 검토 및 수정 |
| Stage 4 | 10~20분 | QC 검증 |
| Stage 5 | 5분 | 문서 생성 |

## 3. Stage 1: 새 보고서 생성

### 3.1 접근 방법
1. 대시보드에서 **"➕ 새 보고서 생성"** 버튼 클릭
2. 또는 상단 메뉴 → **보고서** → **새 보고서**

### 3.2 입력 필드

#### 필수 입력 항목
| 필드명 | 변수 ID | 설명 | 예시 |
|--------|---------|------|------|
| 성분명 | CS0 | 의약품 성분명 (영문/국문) | Acetaminophen |
| 브랜드명 | CS1 | 제품 브랜드명 | 타이레놀정 |
| 회사명 | CS2 | 제조/수입사명 | (주)한국제약 |
| 국내허가일자 | CS5 | YYYY-MM-DD 형식 | 2010-03-15 |
| 보고서 제출일 | CS6 | 제출 예정일 | 2026-06-30 |
| 보고서 버전 | CS7 | 버전 번호 | 1.0 |

#### 선택 입력 항목
| 필드명 | 변수 ID | 설명 |
|--------|---------|------|
| 유효기간 | CS8 | 제품 유효기간 (개월) |
| 1일 사용량 | CS20 | 표준 1일 사용량 |
| 환자당 연간 사용량 | CS21 | 환자 1명당 연간 사용량 |
| MedDRA 버전 | CS24 | 사용된 MedDRA 버전 |

### 3.3 저장 및 다음 단계
1. 모든 필수 항목 입력 확인
2. **"보고서 생성"** 버튼 클릭
3. 성공 시 자동으로 Stage 2로 이동

> ⚠️ **주의**: 생성 후에도 Stage 1에서 기본 정보 수정 가능

## 4. Stage 2: Raw Data 처리

### 4.1 개요
Stage 2는 **3단계 위저드**로 구성:
```
Step 1 (제품정보) → Step 2 (임상자료) → Step 3 (기타자료) → LLM 처리
```

### 4.2 Step 1: 제품정보 문서 업로드 (8개 파일)

| RAW ID | 문서 유형 | 형식 | 필수 |
|--------|----------|------|------|
| RAW1.1 | 최신첨부문서 | PDF | ✅ |
| RAW1.2 | 보고기간시작시점첨부문서 | PDF | - |
| RAW2.1 | 용법용량 | PDF | ✅ |
| RAW2.2 | 효능효과 | PDF | ✅ |
| RAW7 | 안전성정보변경 | DOCX | ✅ |

**업로드 방법**:
1. 파일 선택 또는 드래그 앤 드롭
2. RAW ID 자동 분류 확인 (LLM)
3. 잘못된 분류는 드롭다운으로 수정
4. **"다음"** 클릭

### 4.3 Step 2: 임상 자료 업로드 (2개 파일)

| RAW ID | 문서 유형 | 형식 |
|--------|----------|------|
| RAW8 | 임상노출데이터 | DOCX |
| RAW17 | IIT 및 NIS 트래커 | XLSX |

### 4.4 Step 3: 기타 자료 업로드 (20개 파일)

| RAW ID | 문서 유형 | 형식 |
|--------|----------|------|
| RAW3 | 시판후 Sales 데이터 | XLSX |
| RAW4 | 허가현황 | XLSX |
| RAW5 | 안전성조치 허가팀 메일 | DOCX |
| RAW6 | 안전성조치 허가팀 메일 취합본 | DOCX |
| RAW9 | 문헌자료 | XLSX |
| RAW12 | 국외신속보고 LineListing | XLSX |
| RAW13 | 국내신속보고 LineListing | XLSX |
| RAW14 | 원시자료 LineListing | XLSX |
| RAW15 | 정기보고 LineListing | XLSX |
| RAW16 | MedDRA SMQ (lack of efficacy) | XLSX |

### 4.5 LLM 자동 처리

**"LLM 분류 시작"** 버튼 클릭 시:
1. **마크다운 변환** - PDF/Excel/Word → Markdown
2. **데이터 추출** - CS/PH/Table 데이터 자동 추출
3. **PSUR 섹션 생성** - 15개 섹션 초안 생성

처리 진행 상황은 진행률 바로 확인 가능

> ⚠️ **주의**: 총 30개 파일이 모두 업로드되어야 LLM 처리 시작 가능

## 5. Stage 3: 섹션 편집

### 5.1 15개 PSUR 섹션

| 번호 | 섹션명 | 주요 내용 |
|------|--------|----------|
| 00 | 표지 | 보고서 기본 정보, 제출일 |
| 01 | 목차 | 자동 생성 |
| 02 | 약어설명 | 사용된 약어 목록 |
| 03 | 서론 | 제품 개요, 적응증 |
| 04 | 전세계판매허가현황 | 국가별 허가 상태 |
| 05 | 안전성조치 | 안전성 관련 조치 이력 |
| 06 | 안전성정보참고정보변경 | 허가사항 변경 이력 |
| 07 | 환자노출 | 판매량 기반 노출 환자 수 |
| 08 | 개별증례병력 | 이상사례 케이스 |
| 09 | 시험 | 임상 시험 데이터 |
| 10 | 기타정보 | 문헌 자료 등 |
| 11 | 종합적인안전성평가 | 전체 안전성 종합 |
| 12 | 결론 | 유익성-위해성 평가 |
| 13 | 참고문헌 | 인용 문헌 목록 |
| 14 | 별첨 | 첨부 자료 |

### 5.2 섹션 편집 기능

#### 직접 편집
- 마크다운 에디터에서 직접 내용 수정
- 실시간 미리보기 지원

#### AI 지원 기능
- **"AI 재생성"** - 해당 섹션 전체 재생성
- **"AI 수정"** - 선택한 부분만 수정 요청
- **채팅 모달** - LLM과 대화하며 수정

#### 데이터 확인
- 우측 패널에서 추출된 CS/PH/Table 데이터 확인
- 데이터 충돌 시 선택 가능

### 5.3 저장
- **자동 저장**: 30초마다 자동 저장
- **수동 저장**: Ctrl+S 또는 저장 버튼
- 저장 상태는 상단 표시줄에서 확인

## 6. Stage 4: QC 검증

### 6.1 QC 검증 항목

| 카테고리 | 검증 내용 |
|----------|----------|
| 필수 데이터 | CS 변수 누락 여부 |
| 날짜 일관성 | 보고기간, 제출일 등 |
| 수치 일관성 | 판매량, 환자 수 등 |
| 형식 검증 | MedDRA 코드, 날짜 형식 |
| 섹션 완성도 | 각 섹션 내용 충실도 |

### 6.2 QC 결과 확인
- **PASS**: 녹색 체크 표시
- **WARNING**: 노란색 경고 (수정 권장)
- **FAIL**: 빨간색 오류 (수정 필수)

### 6.3 오류 수정
1. 오류 항목 클릭 → 해당 섹션으로 이동
2. 수정 후 저장
3. **"QC 재검증"** 클릭

### 6.4 승인 요청
- 모든 FAIL 항목 해결 후
- **"검토 요청"** 버튼으로 Reviewer에게 전달

---

## 7. Stage 5: 최종 출력

### 7.1 Word 문서 생성
1. QC 승인 완료 확인
2. **"Word 문서 생성"** 버튼 클릭
3. 생성 완료 후 다운로드

### 7.2 출력 옵션
- **전체 출력**: 15개 섹션 모두 포함
- **섹션 선택 출력**: 필요한 섹션만 선택

### 7.3 출력물 확인
- 다운로드된 .docx 파일 열기
- 페이지 번호, 목차 확인
- 표, 그래프 렌더링 확인

## 8. 자주 묻는 질문

### Q1. 보고서 작성 중 저장이 안 됩니다.
**A**: 네트워크 연결 상태를 확인하세요. 오프라인 시 로컬 저장소에 임시 저장됩니다.

### Q2. LLM 처리가 오래 걸립니다.
**A**: 파일 크기와 수에 따라 15~30분 소요됩니다. 진행률 바를 확인하세요.

### Q3. RAW ID 분류가 잘못되었습니다.
**A**: 드롭다운 메뉴에서 올바른 RAW ID를 수동으로 선택하세요.

### Q4. 이전 단계로 돌아갈 수 있나요?
**A**: 예, 좌측 단계 표시기를 클릭하면 이전 단계로 이동 가능합니다.

### Q5. 다른 사용자와 동시 편집이 가능한가요?
**A**: 현재 버전에서는 동시 편집이 지원되지 않습니다. 한 사용자가 편집 중일 때 다른 사용자는 조회만 가능합니다.
