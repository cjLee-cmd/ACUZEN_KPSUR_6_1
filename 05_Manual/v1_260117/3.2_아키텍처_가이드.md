### 1.2 주요 특징
- **서버리스 아키텍처**: GitHub Pages + Supabase

- **멀티 LLM 지원**: Gemini, Claude, OpenAI 통합

## 3. 모듈 아키텍처

### 3.1 레이어 구조

```
┌─────────────────────────────────────────────────────────────────────┐
│  Layer 8: Output                                                     │
│  └── output-generator.js, qc-validator.js, section-editor.js        │
├─────────────────────────────────────────────────────────────────────┤
│  Layer 7: Extract                                                    │
│  └── js/extract/ (extract-cs.js, extract-ph.js, extract-tables.js) │
├─────────────────────────────────────────────────────────────────────┤
│  Layer 6: PSUR                                                       │
│  └── js/psur/ (psur-core.js, psur-sections.js, psur-prompts.js)    │
├─────────────────────────────────────────────────────────────────────┤
│  Layer 5: File                                                       │
│  └── file-handler.js, markdown-converter.js, unified-processor.js   │
├─────────────────────────────────────────────────────────────────────┤
│  Layer 4: LLM                                                        │
│  └── js/llm/ (llm-base.js, llm-gemini.js, llm-claude.js, ...)      │
├─────────────────────────────────────────────────────────────────────┤
│  Layer 3: Database                                                   │
│  └── js/db/ (supabase-core.js, supabase-auth.js, ...)              │
├─────────────────────────────────────────────────────────────────────┤
│  Layer 2: Auth                                                       │
│  └── auth.js, permissions.js, page-guard.js                         │
├─────────────────────────────────────────────────────────────────────┤
│  Layer 1: Config                                                     │
│  └── config.js, env.js                                              │
├─────────────────────────────────────────────────────────────────────┤
│  Layer 0: Core (SEALED - 수정 금지)                                  │
│  └── js/core/ (5개 sealed 모듈)                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.2 Layer 0: Core (Sealed)

> ⚠️ **수정 금지** - 명시적 승인 필요

| 모듈 | 역할 |
|------|------|
| `markdown-transform-core.js` | 마크다운 변환 핵심 로직 |
| `supabase-query-core.js` | DB CRUD 핵심 로직 |
| `llm-provider-core.js` | LLM 추상화 핵심 로직 |
| `data-extract-core.js` | 데이터 파싱 핵심 로직 |
| `file-io-core.js` | 파일 I/O 핵심 로직 |

### 3.3 Layer 3: Database (js/db/)

```
js/db/
├── supabase-core.js      # 초기화, 연결 관리
├── supabase-auth.js      # 인증 (로그인/로그아웃)
├── supabase-reports.js   # 보고서 CRUD
├── supabase-documents.js # 문서/마크다운 CRUD
├── supabase-llm.js       # LLM 다이얼로그 로깅
└── index.js              # 통합 export
```

### 3.4 Layer 4: LLM (js/llm/)

```
js/llm/
├── llm-base.js     # 공통 인터페이스
├── llm-gemini.js   # Google Gemini 구현
├── llm-claude.js   # Anthropic Claude 구현
├── llm-openai.js   # OpenAI 구현
└── index.js        # 팩토리 패턴
```

### 3.5 Layer 7: Extract (js/extract/)

```
js/extract/
├── extract-base.js       # 추출 기본 로직
├── extract-cs.js         # CS 데이터 추출
├── extract-ph.js         # PH 데이터 추출

├── extract-linelisting.js# LineListing 특수 처리
├── format-validator.js   # 형식 검증
└── index.js              # 통합 DataExtractor
```

## 5. 주요 패턴

### 5.1 Global Object Pattern

GitHub Pages 제약으로 ES6 import/export 대신 window 객체 사용:

```javascript
// 모듈 정의
const myModule = {
    doSomething() { /* ... */ }
};

// window에 export
if (typeof window !== 'undefined') {
    window.myModule = myModule;
}
```

### 5.2 KPSUR 네임스페이스

```javascript
window.KPSUR = {
    db: {
        client: supabaseClient,
        core, auth, reports, documents, llm
    },
    llm: {
        client: multiLLMClient,
        base, gemini, claude, openai
    },
    psur: {
        generator: psurGenerator,
        core, sections, templates, prompts
    },
    extract: {
        extractor: dataExtractor,
        base, cs, ph, tables
    }
};
```

### 5.3 팩토리 패턴 (LLM)

```javascript
// js/llm/index.js
const LLMFactory = {
    create(provider) {
        switch (provider) {
            case 'gemini': return new GeminiClient();
            case 'claude': return new ClaudeClient();
            case 'openai': return new OpenAIClient();
            default: return new GeminiClient();
        }
    }
};
```

### 5.4 Async/Await 패턴

```javascript
// 모든 DB/LLM 호출에 async/await 필수
async function fetchReport(reportId) {
    try {
        const { data, error } = await supabaseClient.getReportById(reportId);
        if (error) throw error;
        return data;
    } catch (err) {
        console.error('Report fetch failed:', err);
        throw err;
    }
}
```

## 6. 제약사항

### 6.1 GitHub Pages 제약

| 제약 | 영향 | 해결책 |
|------|------|--------|
| 서버 코드 불가 | 모든 로직 클라이언트 | Supabase 사용 |
| ES6 모듈 제한 | import/export 불가 | window 객체 사용 |
| 환경변수 불가 | .env 사용 불가 | localStorage 사용 |

### 6.2 보안 제약

| 항목 | 현재 상태 | 권장 |
|------|----------|------|
| API 키 | localStorage | 정기 갱신 |
| 인증 | Supabase Auth | RLS 활용 |
| 데이터 | RLS 정책 | 역할별 제한 |

### 6.3 성능 제약

| 항목 | 한도 | 비고 |
|------|------|------|
| 파일 크기 | 50MB | 단일 파일 |
| LLM 토큰 | 모델별 상이 | Gemini 1M, Claude 200K |
| localStorage | 5~10MB | 브라우저별 |
